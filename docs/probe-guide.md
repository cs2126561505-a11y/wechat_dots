# 只读探针与专用环境准备

本探针用于审查 `wechatauto-replica 1.2.6.1` 与微信 `4.1.15.13` 的组合。专用来宾已完成首轮群读取，结果见[验证记录](validation.md)。实时入口要求当前有效的私密准入记录；默认拒绝执行，没有发送命令，也没有 dot 或 MCP Events 连接。

## 专用 Windows 环境

所有者已选择 Windows 虚拟机或备用电脑，仅登录测试账号。当前日常电脑有两个微信账号目录，不进行取密钥或解密。它可以继续保存源代码和执行合成测试。

在专用环境内新建独立的微信数据目录，使用普通用户权限运行客户端和探针。只从 Git 仓库取得代码，不复制当前工作区中的 `.runtime`、密钥、微信目录或整个 Windows 用户目录。测试账号的联系人和历史数据也应视为私密数据，因为候选按完整数据库分片解密，群级 SQL 过滤发生在解密之后。

虚拟机只连接测试需要的网络，核对并关闭宿主磁盘/目录共享、自动文件同步、共享剪贴板和拖放，避免把主账号数据暴露给来宾。微软的 Hyper-V 文档说明增强会话可把本地驱动器与剪贴板分享给来宾，这些是需要检查的实际通道。[本地资源共享](https://learn.microsoft.com/en-us/windows-server/virtualization/hyper-v/use-local-resources-virtual-machine-connection)

专用 VirtualBox 来宾已经完成安装与离线验证。实际设备配置、兼容性诊断、账号目录和系统检查记录仅保存在本地。

## 可复现的准备与离线检查

使用 Python 3.12 64 位，在仓库根目录的 PowerShell 中运行：

```powershell
py -3.12 -m venv .venv-probe
$probePython = ".\.venv-probe\Scripts\python.exe"
& $probePython -m pip install -r requirements-dev.txt -r requirements-probe.txt
& $probePython scripts/fetch_probe_source.py
& $probePython -m unittest discover -s tests -v
& $probePython -m wechat_probe audit
```

额外依赖仅为 `cryptography`、`psutil` 和 `zstandard`。不安装上游完整自动化包。源码获取脚本核对固定提交与文件哈希；`audit` 只核对源码和输出准入结论，不加载微信数据库。

`python -m wechat_probe discover` 读取客户端版本、进程元数据和账号目录列表，并输出目录索引与脱敏别名。它会加载经过哈希验证的数据库模块定义，但不会构造数据库对象、调用取密钥函数或查询聊天内容。一个账号目录也不会被视为已证明隔离。

`bind` 和 `watch` 在缺少有效准入时返回退出码 `2`，并在创建私密运行状态前停止。本地操作者复核虚拟机共享配置后，在来宾用户的 `LocalAppData/WeChatDotsLab/admission.json` 建立至多 15 分钟的记录，绑定来宾身份、用户、进程及唯一账号目录。普通权限探针校验客户端哈希、资源状态和绑定关系。SMB 连接仍使用 `Get-SmbConnection`，普通权限受限时只接受管理员写权限保护且 20 秒内更新的同一查询结果；映射列表不能替代该查询。虚拟环境只隔离 Python 依赖，不能隔离主账号文件或微信进程。

## 通过隔离审查后的测试设计

先确认微信客户端精确版本、唯一测试账号、进程所属用户与创建时间、账号数据路径、缓存路径及权限。测试环境应排除主账号数据及其共享入口。短时准入将操作者的宿主配置检查与来宾自动核验结合；它用于避免误操作，无法对抗拥有管理员权限的修改者。

读取放行后，按 `test-group` 精确查询联系人库中的群身份。零个或多个真实群 ID 都停止。建立启动时的分片游标，不回填历史记录。客户端或账号变化后重新审查绑定；不自动换进程或账号。后续只观察本次随机标记的测试消息。

| 对照样本 | 由谁操作 | 需要核对的事实 |
| --- | --- | --- |
| 普通文本 `标记_PLAIN` | 群内另一个受控账号 | 来源群与成员 ID 可靠，元数据明确没有 @ 测试账号 |
| 真实 @ 加 `标记_REAL_AT` | 同一个受控账号，在微信界面选择成员完成 @ | 元数据明确包含测试账号真实 ID |
| 手打假 @ 加 `标记_FAKE_AT` | 同一个受控账号，只输入显示文本 | 不得因为正文出现 @ 或昵称判定为真实 @ |
| 自身消息 `标记_SELF` | 测试账号 | 成员 ID 等于已绑定测试账号，排除自身触发 |
| 重复读取与重启探针 | 操作者 | 分片加消息编号去重，游标与记录持久化，不重复产生事件 |
| 断线与同名会话 | 操作者 | 记录缺口和重新绑定情况；不误选另一同名群或私聊 |

`source` 中的 XML `atuserlist` 已在本轮真实 @ 样本中观察到，入站数据可能经 Zstandard 压缩，解析上限为 16 KiB。没有字段、格式不认识或无法区分普通文本与假 @ 时，结果保持未知，不能从正文猜测。合成测试标记只帮助关联样本；样本标签本身不证明用户确实执行了真实 @，需要操作记录与实际元数据共同确认。手机输入不便时，可以改用用户确认的短文本，并限定同一群、本轮时间窗口与明确的操作顺序；这属于本地诊断流程，CLI 的标记过滤仍保留。

读取验证通过后，单独审查发送实现。先让所有者确认唯一固定回复正文，再验证桌面目标与真实群 ID 的关联，发送后按群 ID、正文、发送者和时间核对数据库，并由接收端确认。结果不明停止重发。当前上游桌面路径尚未满足该要求，探针不发送消息。

## 记录与停止

公开仓库仅保存版本、哈希、场景通过/未通过结论和合成样例。原始消息、成员 ID、账号目录、密钥与解密文件留在专用环境内。测试结束后撤销准入并停止辅助检查，再按所有者需要保留或清理已生成的私密缓存。

当前命令失败会给出脱敏原因，不打印上游原始异常。隔离不明、版本变更、账号或进程变化、群名冲突、源字段不可靠及发送确认不明，都是停止条件。正式群策略仍为关闭、空白名单、草稿模式；只有完成通道验收后才讨论新增正式适配器与 MCP Events。
