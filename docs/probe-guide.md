# 只读探针与专用环境准备

2026-10-18 更新：增加独立的 `wechat_probe.sender` 文本发送测试执行器。它复用私密来宾准入和真实账号、群绑定，核对完整批准正文及当前原生控件，持久化一次性动作记录，再回查同群消息分片。实际按钮点击已在单独批准的一次测试中取得数据库回执及接收端确认；每次仍须明确选择发送方式，未知结果会阻止后续自动发送。读取与界面只读命令保留原有边界，当前操作结果以[验证记录](validation.md)的最新结论为准。

本探针用于审查 `wechatauto-replica 1.2.6.1` 与微信 `4.1.15.13` 的组合。实时入口要求当前有效的私密准入记录。独立批准文本收发、真实事件发布、原 dot 唤醒、中文草稿保存和审核后原群回发均已取得实测证据。测试结束后撤销读取许可并停止临时监控，后续恢复仍须当前有效的专用来宾准入。

## 专用 Windows 环境

所有者已选择 Windows 虚拟机或备用电脑，仅登录测试账号。当前日常电脑有两个微信账号目录，不进行取密钥或解密。它可以继续保存源代码和执行合成测试。

在专用环境内新建独立的微信数据目录，使用普通用户权限运行客户端和探针。只从 Git 仓库取得代码，不复制当前工作区中的 `.runtime`、密钥、微信目录或整个 Windows 用户目录。测试账号的联系人和历史数据也应视为私密数据，因为候选按完整数据库分片解密，群级 SQL 过滤发生在解密之后。

虚拟机只连接测试需要的网络，核对并关闭宿主磁盘/目录共享、自动文件同步、共享剪贴板和拖放，避免把主账号数据暴露给来宾。微软的 Hyper-V 文档说明增强会话可把本地驱动器与剪贴板分享给来宾，这些是需要检查的实际通道。[本地资源共享](https://learn.microsoft.com/en-us/windows-server/virtualization/hyper-v/use-local-resources-virtual-machine-connection)

专用 VirtualBox 来宾已经完成安装与离线验证。实际设备配置、兼容性诊断、账号目录和系统检查记录仅保存在本地。

## 可复现的准备与离线检查

使用 Python 3.12 64 位，在仓库根目录的 PowerShell 中运行：

```powershell
py -3.12 -m venv .venv-probe
$probePython = ".\.venv-probe\Scripts\python.exe"
& $probePython -m pip install -r requirements-dev.txt -r requirements-probe.txt
& $probePython scripts/fetch_probe_source.py
& $probePython -m unittest discover -s tests -v
& $probePython -m wechat_probe audit
```

额外依赖仅为 `cryptography`、`psutil` 和 `zstandard`。不安装上游完整自动化包。源码获取脚本核对固定提交与文件哈希；`audit` 只核对源码和输出准入结论，不加载微信数据库。

`python -m wechat_probe discover` 读取客户端版本、进程元数据和账号目录列表，并输出目录索引与脱敏别名。它会加载经过哈希验证的数据库模块定义，但不会构造数据库对象、调用取密钥函数或查询聊天内容。一个账号目录也不会被视为已证明隔离。

`bind`、`watch` 和 `publish` 在缺少有效准入时返回退出码 `2`，并在创建私密运行状态前停止。本地操作者复核虚拟机共享配置后，在来宾用户的 `LocalAppData/WeChatDotsLab/admission.json` 建立至多 15 分钟的记录，绑定来宾身份、用户、进程及唯一账号目录。普通权限探针校验客户端哈希、资源状态和绑定关系。SMB 连接仍使用 `Get-SmbConnection`，普通权限受限时只接受管理员写权限保护且 20 秒内更新的同一查询结果；映射列表不能替代该查询。虚拟环境只隔离 Python 依赖，不能隔离主账号文件或微信进程。

## 通过隔离审查后的测试设计

先确认微信客户端精确版本、唯一测试账号、进程所属用户与创建时间、账号数据路径、缓存路径及权限。测试环境应排除主账号数据及其共享入口。短时准入将操作者的宿主配置检查与来宾自动核验结合；它用于避免误操作，无法对抗拥有管理员权限的修改者。

读取放行后，按 `test-group` 精确查询联系人库中的群身份。零个或多个真实群 ID 都停止。建立启动时的分片游标，不回填历史记录。客户端或账号变化后重新审查绑定；不自动换进程或账号。后续只观察本次随机标记的测试消息。

| 对照样本 | 由谁操作 | 需要核对的事实 |
| --- | --- | --- |
| 普通文本 `标记_PLAIN` | 群内另一个受控账号 | 来源群与成员 ID 可靠，元数据明确没有 @ 测试账号 |
| 真实 @ 加 `标记_REAL_AT` | 同一个受控账号，在微信界面选择成员完成 @ | 元数据明确包含测试账号真实 ID |
| 手打假 @ 加 `标记_FAKE_AT` | 同一个受控账号，只输入显示文本 | 不得因为正文出现 @ 或昵称判定为真实 @ |
| 自身消息 `标记_SELF` | 测试账号 | 成员 ID 等于已绑定测试账号，排除自身触发 |
| 重复读取与重启探针 | 操作者 | 分片加消息编号去重，游标与记录持久化，不重复产生事件 |
| 断线与同名会话 | 操作者 | 记录缺口和重新绑定情况；不误选另一同名群或私聊 |

`source` 中的 XML `atuserlist` 已在本轮真实 @ 样本中观察到，入站数据可能经 Zstandard 压缩，解析上限为 16 KiB。没有字段、格式不认识或无法区分普通文本与假 @ 时，结果保持未知，不能从正文猜测。合成测试标记只帮助关联样本；样本标签本身不证明用户确实执行了真实 @，需要操作记录与实际元数据共同确认。手机输入不便时，可以改用用户确认的短文本，并限定同一群、本轮时间窗口与明确的操作顺序；这属于本地诊断流程，CLI 的标记过滤仍保留。

读取验证通过后，单独审查发送实现。先让所有者确认唯一固定回复正文，再验证桌面目标与真实群 ID 的关联，发送后按群 ID、正文、发送者和时间核对数据库，并由接收端确认。结果不明停止重发。独立发送器已按此流程取得首条文本证据，上游完整桌面模块仍未导入。

## 受限事件投递

`publish` 读取已核验的群和账号绑定，首次运行时建立新的分片游标。投递范围限定为明确真实 @ 测试账号、由配置中受控真人账号发出的新文本；自身消息、未知成员和未知 @ 跳过。正文上限 4096 字符，消息有效期 5 分钟，单次运行上限 15 分钟。原来的 `watch` 保留诊断标记筛选，`publish` 使用来源元数据和受控发送者筛选。

在来宾的 `.runtime/<run>/` 私密目录内，按 [配置示例](../config/bridge.example.json) 建立 `bridge.json`，填写与读取绑定一致的真实账号、群 ID 和受控发送者 ID。`bridge-token.txt` 保存绑定到相同账号和群的独立适配器凭据；该凭据由网关管理端另行签发，所有者口令和 dot 的 OAuth 令牌各自保持独立。网关启用与绑定仍需完成准入，默认部署拒绝投递。

```powershell
& .\.venv-probe\Scripts\python.exe -m wechat_probe --run reviewed-run publish --seconds 300
```

`bridge.sqlite3` 原子保存读取游标与待投递正文。网络失败或接收回执丢失后，使用同一消息标识重试，网关重复接收只保留一条事件；账号、进程或配置变化时停止恢复。HTTPS 校验证书并拒绝重定向，证书校验失败、认证失败和其他确定的请求错误停止本次运行。过期消息停止投递，确认或过期后逻辑清空待投递正文；私密 SQLite 文件的物理清理随实验缓存统一安排。命令只输出聚合计数，排除正文、真实标识和凭据。离线测试已覆盖筛选、断点恢复、丢失回执、冲突回滚及隔离检查；实际来宾采集、公网发布和原 dot 回调已通过首次受控回路，长期恢复行为仍待后续验证。

## 只读界面能力检查

`wechat_probe.ui_probe` 用于判断当前微信窗口是否直接提供 Windows UI Automation 控件信息，为后续发送方案提供证据。它使用 Windows 自带的 `UIAutomationClient`、`UIAutomationTypes` 和隐藏的 PowerShell 工作进程，沿控件树读取属性，无需安装额外 Python 包。接口依据微软的 [AutomationElement 文档](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.automationelement)和 [TreeWalker 文档](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.treewalker)；工作进程采用独立的 MTA 线程环境，符合[客户端线程说明](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-threading)。

入口先核验现有专用来宾许可。窗口筛选使用该许可绑定的主进程 ID，继续核对进程创建时间、当前 Windows 会话和每个控件的进程归属。运行前后许可必须一致。该命令仍要求当前 SMB 检查等隔离条件有效；准备好许可后，在专用来宾运行：

```powershell
& .\.venv-probe\Scripts\python.exe -m wechat_probe.ui_probe --run ui-readonly --seconds 15 --max-nodes 256
```

默认观察上限为 15 秒、256 个节点、8 层深度和 16 个匹配窗口；可将时间调整到最多 30 秒。独立父进程另留 10 秒给启动、编译及退出，超时会终止工作进程。工作进程遵循来宾已有的 PowerShell 执行策略，策略阻止启动时返回失败。控件提供方卡住、窗口消失或达到限制时，结果保持受限或失败状态，不能据此推断微信完全缺少辅助功能支持。

详细报告保存到来宾 `.runtime/ui-readonly/ui-snapshot-<本次随机编号>.json`，包含有限长控件名称、类型、AutomationId、类名及 Text/Value pattern 是否可用。名称本身可能包含会话标题或消息正文，因此报告留在来宾私密目录。命令行只输出控件类型与数量、输入候选数、模式数量和固定状态；工作进程的标准输出与错误输出均丢弃。密码控件名称被留空，输入值和 TextPattern 中的文本不读取。

该组件只观察属性，绝无点击、焦点切换、键入、发送或辅助功能设置变更，也不加载上游界面模块及 `ensure_materialized` 路径。它没有进程内存读写或注入接口。报告中的输入候选与模式可用标志只说明接口暴露情况，尚未证明可编辑、能够定位真实群 ID 或可以可靠确认发送结果。本组件已完成离线门禁、超时、输出脱敏和报告验证；真实来宾的控件能力仍需单独实测。

## 记录与停止

公开仓库仅保存版本、哈希、场景通过/未通过结论和合成样例。原始消息、成员 ID、账号目录、密钥与解密文件留在专用环境内。测试结束后撤销准入并停止辅助检查，再按所有者需要保留或清理已生成的私密缓存。

当前命令失败会给出脱敏原因，不打印上游原始异常。隔离不明、版本变更、账号或进程变化、群名冲突、源字段不可靠及发送确认不明，都是停止条件。正式群策略仍为关闭、空白名单、草稿模式；只有完成通道验收后才讨论新增正式适配器与 MCP Events。
